# Acceptance runs unattended: a bleak Harness for the board, Playwright over CDP for the Web App

Firmware behaviour (Brightness applied and confirmed by the Duty readback marker on the serial console, Heartbeats arriving with consecutive `seq`, Brightness kept across a disconnect and reconnect) is checked by a Python Harness that acts as a Central through `bleak`. The Web App is checked in real Chrome driven by Playwright for Python, which answers the native Web Bluetooth device chooser through the Chrome DevTools Protocol `DeviceAccess` domain (unverified: read from the CDP documentation, not yet tried on this PC). Both live in the project's own `.venv`; west, twister and esptool stay in the Zephyr venv. Python was chosen over Puppeteer because this PC has no Node.js. Bluefy on iOS remains a human acceptance run.
