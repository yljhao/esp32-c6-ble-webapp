# Flash through esptool-build: `west flash` day to day, `build.sh flash` pinned to the C6 for acceptance

Both paths run the local esptool-build (launcher `~/zephyrproject/.venv/bin/esptool`, which imports the esptool-build working tree); upstream esptool is not to be installed. Since esptool-build f22af07, plain `west flash -d build` detects the chip from `chip_id` and picks the single USB-Serial/JTAG port (verified on this XIAO by the esptool-build session with a scratch image; unverified with this project's image until the first flashing ticket). Auto-detection flashes whatever chip is attached, so the Harness and acceptance flash through `build.sh flash`, which passes `--chip esp32c6` and `--port` explicitly and is refused on any other chip. Never `west flash --no-reset` (Zephyr 4.4.2's runner then drops `write-flash -u`), `--erase` or `--esp-encrypt` (unsupported by esptool-build). Supersedes the reference project's ADR-0004 rule "never `west flash`", which held only before f22af07.
