# The Shell link is the Zephyr shell carried over NUS

The Web App talks to the board through the Zephyr shell on a Nordic UART Service transport: it types `led set <n>` / `led get` and reads text lines back, and Heartbeats travel on the same stream as JSON lines (`{"seq":N,"uptime_ms":N}`) the page tells apart from command replies by their leading `{`. We chose this over a custom GATT service (a Brightness characteristic plus a Heartbeat notify characteristic) and over a bespoke line protocol, so the same commands work on the serial console and over BLE and the page needs only one characteristic pair. Cost: upstream Zephyr 4.4.2 has `BT_ZEPHYR_NUS` but no shell backend over it (verified by source search 2026-09-30; that backend exists only in NCS), so this project writes its own shell transport, with echo, prompt and VT100 off on that instance. No pairing: the Shell link exposes only the `led` commands and read-only status commands, never kernel or device commands; `shell_set_root_cmd()` applies to every shell instance (read from `shell.h`), so the restriction needs its own per-instance mechanism.
